## 2. Architecture and authority

Draw normal task and update/recovery flows. Label each source, destination, principal, trusted policy source, persisted data and permission decision. Include model, tokenizer, template, adapter, dependencies, ingestion, identity, connector, audit, diagnostics, support and removable media. Mark where data is trusted as evidence but not executable authority.

## 4. Prioritized threat register

| Causal actor / path / consequence | Priority and uncertainty | Control / owner | Authorized negative test | Evidence state / residual decision |
|---|---|---|---|---|
| Source editor injects export request; broad adapter discloses notes | High consequence; synthetic scenario | Remove export / app owner | Hostile proposal denied before side effect | Fill actual observation; no model efficacy claim |
| Tenant A requests B's note using changed ID | High consequence | Per-resource authorization / app owner | Unknown and foreign IDs denied without content | |
| Supplier artifact and adjacent manifest replaced together | Integrity concern | Trusted expected identity / release owner | Tampered bytes plus new hash rejected | Fixture-only; signed provenance open |
| Logs/diagnostics leave required physical premises | Hard policy conflict | Remove path / operations owner | Inspect actual destination and disable external path | BLOCKED until conflict removed |
| Add conventional API/platform and recovery path | | | | |

Use course states: UNVERIFIED before adequate evidence, BLOCKED for a known hard conflict, bounded test PASSED/FAILED for an observed control, and explicit approval only by the authorized reviewer. Lab DECLARED_ONLY is a declaration state, not independent verification. Do not average away a conflict.

## 5. Validation authorization and evidence

Record environment owner, written scope, permitted methods, time window, synthetic data, rate/impact limits, stop conditions and escalation contact. Name expected denial, pre/post resource state, audit evidence, tested revision and retest trigger. Keep failed cases. Separate policy-fixture tests from real-model attack evaluation, platform assessment and facility inspection.

## 6. Containment and decision

If a failure appears, disable the affected capability, revoke credentials, isolate suspect assets, preserve minimized evidence and identify exposed records. Name incident, platform, application and data owners. Re-test on a dated fixed revision; capture the residual risk and independent sign-off gap. Changes to models, templates, permissions, assets, destinations, operators or recovery reopen review.

## 7. Distinct PM rubric: 20 points

| Criterion | Points |
|---|---:|
| Specific protected outcome, actors and complete boundary | 4 |
| Causal normal/administrative flows and component inventory | 4 |
| Prioritized threats with independent controls and owners | 4 |
| Authorized tests, expected denials, evidence and limitations | 4 |
| Containment, residual decision and dated retest triggers | 4 |

A complete draft is 16/20 or higher for the educational exercise, with all hard conflicts still BLOCKED and missing assurance still open. This threshold never authorizes enterprise deployment. A document omitting off-site diagnostics, trusted artifact identity or tenant/resource checks needs revision regardless of its arithmetic total.
