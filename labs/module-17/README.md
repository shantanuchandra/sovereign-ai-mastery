# Module 17 lab: versioned synthetic release operations

Educational draft, 28 November 2026. This single-process Python exercise creates no model service, network request, registry server or real identity/key infrastructure. All requests, tenants, token counts and gate results are synthetic. Independent and production assurance NOT COMPLETED; Module 04 remains HOLD.

## Run

Python 3.11+ standard library; compatible CPU, no GPU/Docker, accounts or paid spend. Allow 60–90 minutes for inspection/adverse tests plus the PM exercise.

```bash
python3 labs/module-17/release_ops.py
python3 -m unittest discover -s labs/module-17 -p 'test_*.py' -v
```

The retained actual [observation](observed-operations-run.json) is deterministic and regenerated by running the first command. It records two activated synthetic bundles, ten admitted tenant-a requests, nine good events, 90% observed success versus a fictional 95% target, a rechecked previous release activated and external-trace deployment denied. No actual model quality is measured.

## Trace the controls

1. Inspect `manifest()` and `fingerprint()`: canonical JSON binds the declared model, runtime build, prompt, retrieval, policy and telemetry schema. The model digest hashes a fictional version string, not actual weights.
2. `register()` copies input; it does not approve it. `eligible()` rehashes retained state to detect in-memory mutation, then checks revocation, declared boundary and exact gate set.
3. `approve()` and `deploy()` are distinct. Their fixture methods have no real caller authentication or role separation. A production authorizer must enforce both.
4. `request()` checks the active release each time, validates synthetic tenant/numeric input, deduplicates tenant/request pairs and applies a per-process count quota. This is not a time-window rate limit. Request IDs remain in process memory but are omitted from emitted events.
5. `metrics()` measures one tenant's admitted requests. Good means `ok` and latency ≤200 ms. Quota denials and duplicates are excluded from this indicator and need separate production user-experience measures. Empty populations are NO_DATA.
6. `rollback()` rechecks approval and current eligibility. It changes an active pointer; it does not restore databases or reverse prior actions.

## Adverse experiments and acceptance

Change every protected artifact category, including OCR and speech outputs to EXTERNAL, remove an artifact, tamper with the registered manifest, revoke an approved bundle, fail a gate and try rollback after revocation. A known conflict must be BLOCKED even if another field is missing; incomplete declarations remain UNVERIFIED. Favorable declarations are DECLARED_ONLY, never verified physical isolation.

Send a prompt containing a unique synthetic marker, inspect `events`, and confirm it is absent. Tenant/release/timing metadata can still be sensitive; this exercise does not implement authentication, access control on logs, deletion, durable deduplication or protected audit storage. Restarting loses all state. No runtime memory or host administrator protection is claimed.

For ten admitted requests at a 95% target, budget is `10 × (1 − .95) = .5` bad requests. One bad request consumes twice that budget and returns FREEZE_AND_REVIEW. Floating-point display may show a value close to .5 or2; this is arithmetic, not a precise production estimator. Token values are supplied fixtures, with no tokenizer or money calculation.

Acceptance: all tests pass, the actual demo record matches, denied candidates do not activate, prompt bodies never enter emitted events, and missing/blocked evidence remains distinct. Physical placement, air-gap controls, real workload quality, actual identity, distributed/durable recovery, production capacity, Arabic/domain review and qualified legal review stay open.
